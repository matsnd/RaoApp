## 🔴 KRYTYCZNE (P0 — blokują produkcję)

### 1. Race condition w `generate_contract_number` → duplikaty numerów umów
- **Plik:** `backend/contracts/service.py:12-30`
- **Potwierdzone w DB:** 2 grupy duplikatów `number` (`111`×2, `S142/2026`×2), 5 grup duplikatów `auto_number` (397-401)
- **Root cause:** `SELECT MAX(auto_number)` bez locka (`FOR UPDATE`), brak `UNIQUE` constraint na `Contract.number`
- **Exploit:** 2 równoległe POST `/contracts` → obie umowy dostają ten sam numer
- **Fix:** `UNIQUE` na `Contract.number` + `SELECT ... FOR UPDATE` na Company(id=1) + retry na `IntegrityError`

### 2. XSS / HTML Injection w generowaniu PDF
- **Plik:** `backend/reports/service.py:581` (Jinja2 bez `autoescape=True`), `:147,164,377-380,490-502` (f-string HTML z DB)
- **Exploit:** Kontrahent o nazwie `<img src="file:///etc/passwd">` → SSRF + wyciek plików przez WeasyPrint
- **Fix:** `Environment(..., autoescape=True)` + `markupsafe.escape()` w f-stringach lub przepisać na Jinja2 template

### 3. `recalculate_total` używa błędnej logiki (nie kaskadowej)
- **Plik:** `backend/contracts/service.py:565-582`
- **Bug:** Liczy `SUM(rate1 * period_count)` zamiast algorytmu kaskadowego z `stats/calc.py`
- **Ignoruje:** `quantity`, `billing_frequency`, `rate2` ("powyżej"), `unit_price` fallback
- **Przykład:** Pozycja z `rental_days=10, quantity=2, [{rate1:100, period_count:5}, {rate1:80, period_count:999}]` → `80 420` zamiast `1 800`
- **Fix:** Przepisać na `calculate_position_value()` per pozycja × `quantity`

### 4. Update schemy nadpisują domyślne wartości (lost data)
- **Plik:** `backend/contracts/service.py:369-378` (update_contract), `467-475` (update_position), `500-509` (update_condition)
- **Bug:** `ContractCreate` używany do update — Pydantic wypełnia brakujące pola domyślnymi, `setattr` nadpisuje wszystko
- **Przykład:** Umowa z `working_days_per_week=5` → PUT z `{notes: "test"}` → `working_days_per_week` wraca do `6`
- **Fix:** Osobne schemy `ContractUpdate` z opcjonalnymi polami + `data.model_dump(exclude_unset=True)`

### 5. `build_contract_data` mutuje obiekty w sesji (data corruption w PDF)
- **Plik:** `backend/reports/service.py:76-83`
- **Bug:** Modyfikuje `f.description` obiektu `ContractServiceFee` attached do sesji → trwała zmiana w DB
- **Przykład:** Opis `"Koszt od $1 zł do $2 zł"` → po PDF zostaje `"Koszt od 150,00 zł do 300,00 zł"`
- **Fix:** Kopiować `desc = f.description` lokalnie, modyfikować kopię

### 6. N+1 queries — 5 krytycznych miejsc
- `contracts/service.py:185-193` — lista umów: **101 zapytań** per request (50 contractor + 50 salesperson)
- `contracts/service.py:271-280` — lista przeterminowanych: **101 zapytań**
- `contracts/service.py:415-428` — lista pozycji: **~25 zapytań** per umowa
- `articles/service.py:46-68` — lista artykułów: **~151 zapytań**
- `contractors/service.py:37-49` — lista kontrahentów: **~51 zapytań**
- **Fix:** `selectinload` lub batch-fetch `IN (...)`

### 7. `/explorer/locations/{city}` — load ALL contracts do Python + regex
- **Plik:** `backend/explorer/router.py:671-846`
- **Bug:** Pobiera wszystkie kontrakty z `delivery_address != ""` do Pythona, filtruje regexem per row
- **Impact:** 15k rekordów do aplikacji + 15k×regex + 10-15 dodatkowych zapytań w pętli
- **Fix:** Filtrować `Contract.city` w SQL (kolumna istnieje!)

### 8. `/stats/positions` — double `_compute_position_revenues` + brak paginacji
- **Plik:** `backend/stats/router.py:695-781`
- **Bug:** `_compute_position_revenues` wywołane 2× (linia 721 i 748), brak LIMIT
- **Impact:** 2× pełny dataset do pamięci, potencjalny OOM
- **Fix:** Jeden wywołanie + paginacja

### 9. Frontend: Auth flow — baseURL hardcoded, logout nie czyści stores
- **Plik:** `composables/useApi.js:4` (baseURL hardcoded `/rao/api`), `stores/auth.js:33-38` (logout nie czyści stores)
- **Bug:** `window.location.href = '/login'` zamiast `router.push` — tracony cały stan, brak redirect
- **Fix:** `baseURL: import.meta.env.VITE_API_URL` + `resetAllStores()` w logout + `router.push('/login?redirect=...')`

### 10. Frontend: Memory leaks — event listenery i timery bez cleanup
- **Pliki:** `DashboardView.vue:420-421` (addEventListener bez removeEventListener), `ContractFormView.vue:1500,1695,1790` (timery bez clearTimeout w onUnmounted)
- **Fix:** `onUnmounted(() => { removeEventListener(...); clearTimeout(...) })`

### 11. Frontend: `localStorage.getItem('token')` zamiast `rao_token`
- **Plik:** `views/ContractFormView.vue:1073`
- **Bug:** Auto-uzupełnianie miasta z kodu pocztowego nigdy nie działa (zawsze null)
- **Fix:** `localStorage.getItem('rao_token')`

### 12. Frontend: `handleSave` waliduje tylko `contractor_id`
- **Plik:** `views/ContractFormView.vue:1337-1374`
- **Bug:** Można zapisać umowę bez dat, z ujemną wartością, z `date_from > date_to`
- **Fix:** Walidacja required fields, date ranges, numeric ranges przed submit

## 🔴 KRYTYCZNE — KATEGORYZACJE NIE FEEDUJĄ STATYSTYK

> **Kontekst użytkownika:** "pamiętaj że te kategoryzacje miały pomóc w zbieraniu statystyk"
>
> Audyt wykazał że kategoryzacje (kategorie, branch, is_external) są **niekompletne lub niespójne**, przez co statystyki są błędne lub brakujące.

### K-1: Kategorie maszyn — nazwy niespójne (diakrytyki + spacje)
- **Plik:** DB `articles.category_main` (collation `utf8mb4_unicode_ci`, nie `polish_ci`)
- **Potwierdzone w DB:**
  - `Ładowarki Teleskopowe`: 242 pozycje (71 artykułów)
  - `Ladowarki teleskopowe `: 72 pozycje (34 artykuły, z trailing space!)
  - **To samo wydzierżawienie — split na 2 kategorie w `/by-category`!**
- **Root cause:** Kolumna używa `utf8mb4_unicode_ci` gdzie `Ł ≠ L`. AGENTS.md mówi `utf8mb4_polish_ci` ale kolumna ma `unicode_ci`.
- **Impact:** `/by-category` pokazuje 2 osobne kategorie zamiast 1 → użytkownik widzi rozdzielony przychód
- **Fix:** Normalizacja nazw kategorii (UPDATE) + zmiana collation na `utf8mb4_polish_ci` + TRIM trailing spaces

### K-2: Branch (Gdańsk/Warszawa) — branch_id=NULL dla wszystkich 742 umów
- **Plik:** DB `contracts.branch_id`
- **Potwierdzone w DB:**
  - 50 umów z G suffix w numerze (np. `S045/2026G`) ale `branch_id=NULL`
  - 0 umów z `branch_id` ustawionym
  - **Brak endpointu stats-by-branch** — S/G w numerze nie feeduje żadnych statystyk
- **Impact:** Nie można wygenerować statystyk per oddział (Gdańsk vs Warszawa)
- **Fix:**
  1. Migracja: `UPDATE contracts SET branch_id=2 WHERE number REGEXP '[0-9]G$'` (Gdańsk)
  2. Dodać endpoint `/stats/by-branch` lub filtr `branch_id` w istniejących endpointach

### K-3: is_external — flaga istnieje ale nigdy nie używana
- **Plik:** DB `articles.is_external`
- **Potwierdzone w DB:** 419 artykułów, wszystkie `is_external=0`. 0 pozycji z artykułami zewnętrznymi.
- **Impact:** Flaga istnieje w modelu ale nie feeduje żadnych statystyk (brak filtrowania)
- **Fix:** Zdecydować z klientem czy funkcjonalność maszyn zewnętrznych jest potrzebna. Jeśli tak — wdrożyć. Jeśli nie — usunąć flagę.

### K-4: is_service — działa poprawnie w statystykach ✅
- 337 maszyn (`is_service=0`) + 82 usług (`is_service=1`)
- `/top-machines` poprawnie filtruje tylko maszyny
- `/additional-fees` poprawnie pokazuje usługi
- **Status:** OK, brak problemu

### K-5: is_archival — naprawione w P2-029 ✅
- Wszystkie 419 artykułów `is_archival=1` (po migracji)
- Endpointy historyczne uwzględniają archiwalne (fix P2-029)
- **Status:** OK po naprawie P2-029

### K-6: contract_type (S/U) — nie feeduje statystyk
- 535 umów typ S + 207 umów typ U
- Brak endpointu `/stats/by-contract-type` — nie można porównać przychód najmu vs usługi
- **Fix:** Dodać grupowanie po `contract_type` w `/by-category` lub nowy endpoint

## Rekomendacje architektoniczne

1. **RBAC z tenant isolation** — każdy user widzi tylko swoją filię (`branch_id`), admin widzi wszystko
2. **Centralny audit log** — tabela `audit_log` (kto, kiedy, co, stare vs nowe wartości)
3. **Rate limiting** — in-memory lub Redis na login, forgot-password, PDF generation
4. **Cache layer** — Redis dla statystyk (TTL 5 min), RateType/Category (TTL 1h)
5. **Soft delete** — `is_deleted` flag zamiast hard delete dla umów/kontrahentów
6. **Idempotency keys** — na POST endpoints (contract create, position create)
7. **Refresh tokeny** — httpOnly cookie + short-lived access token (15 min)
8. **CI/CD** — `pip-audit`, `npm audit`, gitleaks, SAST w pipeline
